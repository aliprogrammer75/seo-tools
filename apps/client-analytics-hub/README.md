# Client Analytics Hub (Cloudflare Workers + D1)

پلتفرم داشبورد چندسایتی فارسی/راست‌چین برای مدیریت گزارش‌های SEO و فروش.

## وضعیت ۲۱ اکتبر ۲۰۲۶

- Worker: `client-analytics-hub` / deployed
- D1: `client-analytics-hub`
- Worker URL: https://client-analytics-hub.ashurgeshti75.workers.dev
- Admin UI: `/admin`
- Tenant-specific UI: `/s/<site-slug>`
- MCP JSON-RPC over HTTP: `POST /mcp` (Bearer)
- Source code: `worker.js`; database schema: `schema.sql`.
- Site data is **not** public. All JSON report endpoints require an authenticated session scoped to one tenant or admin.
- Secrets `ADMIN_PASSWORD_SHA256`, `SESSION_KEY`, `MCP_ADMIN_TOKEN` are stored as Cloudflare Worker secrets, not committed here.

## تفکیک سایت و مجوزها

تمام گزارش‌ها با شناسه داخلی `site_id` ذخیره شده و در API فقط پس از احراز هویت فیلتر می‌شوند. مدیر مرکزی می‌تواند همه سایت‌ها را ببیند؛ کاربران `viewer` فقط سایت مربوط به خود را می‌بینند. هر سایت مسیر جداگانه، کاربر اختصاصی و داده‌های مستقل دارد. حساب مشتری از دکمه «دسترسی کارفرما» ساخته می‌شود. پسورد قوی تنها یک بار نمایش داده می‌شود. **تا قبل از ایجاد کاربر مشتری، مشتریان هیچ دسترسی ندارند.**

## داده‌های فعلی

- `moorashin`: snapshot واقعی سفارش‌های پرداخت‌شده WooCommerce، ۲۰۲۶-۰۹-۲۱ تا ۲۰۲۶-۱۰-۲۰.
- `exir`: snapshot واقعی سفارش‌های تکمیل‌شده و دارای پرداخت WooCommerce، همان بازه.
- `apadanasivand`: snapshot واقعی سفارش‌های تکمیل‌شده و دارای پرداخت WooCommerce، همان بازه.
- بقیه سایت‌ها: صفحه و ساختار ایجاد شده، داده هنوز وارد نشده است.
- داده‌های snapshot شامل سفارش، مبلغ کل سفارش به تومان، منبع منتسب به سفارش، نوع صفحه ورود و تعدادی از صفحات ورودی‌اند.
- اطلاعات هویتی مشتری، شماره تماس، آدرس سفارش، IP و کلیدهای فروشگاه به D1 منتقل نشده‌اند.
- داده‌ها **خودکار تازه نمی‌شوند**؛ اتصال امن تکرارشونده به WooCommerce، GA4، GSC و BigQuery مرحله بعدی است.

## راه‌اندازی توسعه

با Node.js و Wrangler:

```bash
npm install -g wrangler
wrangler d1 execute client-analytics-hub --remote --file=./schema.sql
```

برای deploy باید `worker.js` را با یک فایل Wrangler شامل binding `DB` به D1 متصل کرد. هر سه secret باید از طریق `wrangler secret put` ست شوند؛ محتوای آن‌ها به repo اضافه نشود. می‌توان برنامه را به جای Build جدید، به‌صورت ES module Worker منتشر کرد. فایل `worker.js` CSS و JS کلاینت را در همان Worker نگه می‌دارد و به CDN خارجی نیاز ندارد.

## فرمت ورود داده تجمعی (MCP)

نمونه پارامتر ابزار `import_snapshot`:

```json
{
  "site_slug": "moorashin",
  "period_start": "2026-09-21",
  "period_end": "2026-10-20",
  "source": "woocommerce",
  "channels": [
    {"channel": "گوگل", "orders": 72, "revenue_toman": 402835884, "sessions": null}
  ]
}
```

سایر آرایه‌ها: `types` با `page_type` و `landings` با `page_path`, `page_type`. پاسخ MCP ابزارهای مدیریتی `list_sites`، `get_site_dashboard`، `create_site`، `create_viewer` و `import_snapshot` را پشتیبانی می‌کند.

## محدودیت‌ها و معیارهای صحت

1. Snapshot دوره‌ای جایگزین GA4 Event Tracking نیست.
2. درآمد نمایش‌داده‌شده **کل مبلغ سفارش** شامل اقلام و هزینه‌های مرتبط است، نه لزوماً درآمد خالص بدون ارسال و مالیات.
3. صفحه ورودی ذخیره‌شده توسط ووکامرس لزوماً صفحه تأثیرگذار بر تصمیم خرید نیست.
4. هر سایت به API و credentials مخصوص خود نیاز دارد؛ کلیدهای MCP فقط مدیریت داشبوردند.
5. برای تحلیل مسیر کامل خرید، رویدادهای `view_item`, `add_to_cart`, `begin_checkout`, `purchase` باید در GA4 درست ثبت و سپس در BigQuery با شناسه سفارش تحلیل شوند.
6. امکان Health check از API عمومی در محیط ابزار فعلی تأیید نشد؛ Deployment در Cloudflare ۱۰۰٪ است و بررسی دستی مرورگر توصیه می‌شود.
7. برای استفاده عمومی یا چندکارفرمایی گسترده، احراز هویت باید با Cloudflare Access/OIDC، audit log، پشتیبان D1 و نظارت خطا تقویت شود.

## امنیت

ورود admin با رمز تصادفی بلند و هش SHA-256 محرمانه؛ حساب‌های viewer با گذرواژه تصادفی و نمک هش می‌شوند، کوکی احراز هویت `HttpOnly; Secure; SameSite=Strict` و امضای HMAC و عمر ۱۲ ساعت دارد. محدودیت تلاش ناموفق در D1 نگه‌داری می‌شود. همه کوئری‌های گزارش به site_id محدودند. برای استقرار گسترده، KDF قوی‌تر (Argon2id یا PBKDF2)، Cloudflare Access و آزمون نفوذ پیشنهاد می‌شود.


## بهبودهای ۲۲ اکتبر ۲۰۲۶

- افزودن سایت از مدیریت مرکزی؛ «حذف» به‌صورت بایگانی امن با تأیید شناسه سایت اجرا می‌شود و حساب‌های سایت و همگام‌سازی آن فوراً غیرفعال می‌شوند.
- بازگردانی سایت از بایگانی داده‌ها را حفظ می‌کند، اما حساب‌های قبلی و همگام‌سازی‌ها را فعال نمی‌کند.
- نقش `site_manager` فقط به سایت اختصاص‌داده‌شده دسترسی خواندن گزارش دارد. API سرور در تمام درخواست‌ها دسترسی را بر اساس `site_id` تأیید می‌کند.
- مدیر اصلی می‌تواند حساب سایت بسازد، فعال/غیرفعال کند و رمز آن را تغییر دهد. رمز از تابع `PBKDF2-SHA256` با ۱۲۰٬۰۰۰ تکرار ساخته می‌شود. قابلیت اعتبارسنجی هش قدیمی برای کاربران قبلی هم حفظ شده است.
- اتصال WooCommerce در مدیریت مرکزی از طریق `Consumer Key` و `Consumer Secret` با مجوز صرفاً Read پشتیبانی می‌شود. کلیدها در D1 به‌صورت AES-GCM با کلید جداگانه `SYNC_ENCRYPTION_KEY` ذخیره می‌شوند؛ کلید رمزنگاری فقط در Secret های Worker است.
- Worker دارای handler `scheduled` است و Cron واقعی `0 * * * *` در Cloudflare فعال شده است؛ تنها سایت‌هایی که اتصال WooCommerce فعال و معتبر دارند هر ساعت همگام می‌شوند.
- آخرین موفقیت همگام‌سازی به همراه نوع منبع اطلاعات در رابط نمایش داده می‌شود. کلیدهای اتصال و داده‌های خریدار در خروجی داشبورد نمایش داده نمی‌شوند.
- اتصال‌های WooCommerce **هنوز پیکربندی نشده‌اند**. تا ثبت کلیدهای دسترسی برای هر سایت، داده‌ها فقط historical snapshot خواهند بود.
- همگام‌سازی خودکار GA4، GSC، BigQuery و مسیر خرید هنوز اضافه نشده و نباید به‌عنوان قابلیت فعال معرفی شود.
- سطح دسترسی مشتری تا این لحظه ایجاد نشده (جدول `app_users` خالی است). این اقدام باید از پنل مدیریت توسط مدیر مجاز انجام شود.

### آماده‌سازی WooCommerce
1. در وردپرس هر سایت به WooCommerce → Settings → Advanced → REST API بروید.
2. یک API Key جدید با مجوز **Read** ایجاد کنید؛ به هیچ عنوان Read/Write لازم نیست.
3. در داشبورد مرکزی کنار نام همان سایت روی «اتصال ووکامرس» کلیک کنید و کلیدها را در فرم امن وارد کنید.
4. روی «به‌روزرسانی» کلیک کنید تا خطاها یا نخستین همگام‌سازی مشخص شود.
5. اجرای ساعتی بعد از اولین اتصال فعال می‌شود. آخرین زمان دریافت موفق در پنل ثبت خواهد شد.

### مدل تازگی داده
- منبع `woocommerce_auto`: داده سفارش‌های پرداخت‌شده در بازه ۳۰ روز منتهی به روز جاری، بعد از همگام‌سازی موفق.
- منبع `woocommerce`: فایل/اسنپ‌شات تاریخی، بدون تضمین تازگی.
- داده نشست‌ها و نرخ تبدیل با منبع ووکامرس تولید نمی‌شوند؛ نمایش آن‌ها تا اتصال GA4 در داشبورد «—» خواهد بود.
- همگام‌سازی ناموفق با وضعیت `error` ثبت می‌شود؛ داده آخرین گزارش موفق حفظ می‌شود و به‌اشتباه جایگزین نمی‌گردد.
- در سایت‌های پرحجم (بیش از ۱۲۰۰ سفارش در هر وضعیت در ۳۰ روز)، همگام‌سازی متوقف می‌شود تا گزارش ناقص ثبت نشود و باید معماری صفحه‌بندی گسترش پیدا کند.

## اصلاح تجربه کاربری و تحلیل اکتبر ۲۰۲۶

**منتشرشده:**
- سایدبار مدیریت مرکزی فقط در `/admin` فهرست همه سایت‌ها را نمایش می‌دهد.
- در `/s/<slug>` منو اختصاصی هر سایت: نمای کلی، کانال‌های جذب، صفحات ورودی، قیف و مسیر خرید، کیفیت داده. مدیر مرکزی لینک بازگشت به همه سایت‌ها دارد.
- فیلتر دوره گزارش فقط بین دوره‌های تجمیعی واقعاً ذخیره‌شده در D1 انتخاب می‌کند؛ انتخاب تقویم دلخواه هنوز نیازمند سری زمانی روزانه است.
- صفحه کانال‌ها: تغییر شاخص نمودار بین تعداد و مبلغ سفارش، جست‌وجو، جدول سهم تعداد/مبلغ، AOV، کلیک برای جزئیات کانال و CSV.
- صفحه ورودی‌ها: جست‌وجو، نوع صفحه، مرتب‌سازی، صفحه‌بندی ۱۵ ردیفی، بازکردن URL روی دامنه همان مشتری و CSV فیلترشده.
- قیف و مسیر خرید: مراحل مشاهده محصول، افزودن به سبد و Checkout را «داده موجود نیست» نشان می‌دهد تا رویدادهای GA4 اضافه شود. خرید WooCommerce را مجزا نمایش می‌دهد.
- کیفیت داده: نمایش منبع، دوره، آخرین همگام‌سازی موفق، وضعیت اتصال و فهرست داده‌های مفقود.
- تاریخ‌ها در رابط کارفرما شمسی و ساعت‌ها به وقت تهران؛ راهنمای تعریف شاخص‌ها به‌صورت بازشونده در نمای کلی.
- بهبود انتساب منبع: `pl.snapp.ir` و `snapppay` دیگر در یک کانال واحد «اسنپ» ادغام نمی‌شوند. منبع دقیق ارجاع نیاز به بررسی دارد.

**گپ نسبت به ابزارهای BI مانند Metabase (هنوز تکمیل نشده):**
- داده روزانه و مقایسه دو بازه مستقل/سال قبل، انتخاب بازه دلخواه و نمودارهای روند.
- قیف واقعی و مسیر خرید، segment بر اساس محصول/دستگاه/کمپین، انتساب مبتنی بر رویداد.
- GA4، GSC و BigQuery و داده هزینه تبلیغات برای نرخ تبدیل، ROAS و CAC.
- طراحی Drag & Drop، query builder، saved question، cross-filtering عمومی و توسعه نمودارهای متنوع.
- گزارش زمان‌بندی‌شده برای مشتری، هشدار افت فروش و خطای ترکینگ، audit trail، نسخه‌بندی نمودارها.
- تست امنیتی End-to-End نقش‌های کارفرما در محیط production و کنترل لایه دسترسی.
- امکان Drill-down به صفحات مشاهده‌شده در هر کانال نیازمند ذخیره داده ردیفی مشترک بین سفارش/صفحه است. از داده‌های تجمیعی فعلی قابل استنتاج نیست.
